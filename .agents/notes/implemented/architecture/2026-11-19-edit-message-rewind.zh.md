# Agent Note: 编辑已发送消息通过空的 surface 替换回退 Session

Status: implemented

[English](2026-11-19-edit-message-rewind.md) | 中文

## 问题

已发送用户消息下方的铅笔会打开就地编辑器，但保存只把编辑后的文本写入 composer 草稿。随后发送时，它作为普通提示追加在现有对话之后：模型仍能看到原消息及其所有回复，Chat 也同时保留两个版本。用户期望编辑像其他聊天产品一样替换这条消息及其后的所有内容。Session 日志只能追加，已发布日志不能改变形态，模型可见历史也必须能从日志重建。

## 决策

`session/editMessage({ requestId, sessionId, seq, text })` 把空闲的普通 Session 回退到一条已发送、开启轮次的 `user/message`，并把编辑后的文本作为新一轮排队。在 `agent.runMaintenance()` 内且 inbox 没有待处理输入时，Session API 追加一条空的 `user/message`，其 `source.kind` 为 `rewind`，surface 操作替换被编辑轮次的第一个模型可见节点直到当前最后一个节点；`sourceEventSeqs` 列出所有被遮蔽的节点。随后以合并进原内容块的编辑文本（附件因此保留）和同一请求身份调用 `agent.followup()`。维护结束时，锁存的唤醒启动新一轮。

### 复用现有 surface 操作，而非新增事件

surface 替换本就允许任何生产方遮蔽一段模型可见节点；压缩依赖它，旧读取方也能折叠它。回退就是不带替换内容的同一操作，因此日志保留所有被撤回的记录，不需要新的事件类型或 `SESSION_FORMAT_VERSION` 变化，回放会重现相同的模型历史。撤回可通过 `rewind` 来源识别，不认识它的消费方按默认分支处理。

### 空的 user 节点不发送内容

`deriveEventMessage` 现在把空内容的 `user/message` 投影为无消息，与空的 system、developer 和 assistant 节点一致。因此撤回不增加线上消息，空的手动继续输入也不再发送部分提供方会拒绝的无内容用户轮次。两者都保留其 surface 位置。

### 编辑后的消息走普通提示路径

把编辑文本作为后续消息排队，复用了提示准入、请求身份去重、继续资格、轮次边界以及 Chat 对开启轮次消息的交流分组。AgentLoop 和 inbox 都不需要了解编辑。维护所有权排除了运行中的轮次，因此撤回不会与模型请求竞争。

### Chat 隐藏被撤回的范围

Conversation 装配器为所有 View 移除每次撤回的范围：从被编辑轮次的开始（若该开始未加载，则从已加载窗口的开始）直到撤回消息。Inbox splice 事件保留在窗口中：它们不渲染任何内容，而 Chat 把它们折叠为一条有序的索引历史，缺口会破坏这段历史。实时到达的撤回，或在含有撤回的窗口中加载更早的页面，都会重放已加载窗口。Trajectory 和导出仍读取完整日志。

## 考虑过的替代方案

**写入 composer 让用户重新发送。** 这是此前的行为；原交流仍对模型可见，正是用户反馈的问题。

**用 `fork` 分支到新 Session。** 在消息之前的事件处分叉今天就能工作，但原 Session 会与分支并存，用户正在查看的 Session 也会改变。用户要求编辑就地发生。

**专用的回退事件类型。** 新类型需要格式决策、每个消费方的读取支持和迁移规则，而 surface 替换已经能表达“这些节点不再到达模型”。

**通过 inbox 携带替换意图，并把编辑后的消息作为替换追加。** 这会把编辑引入 AgentLoop 准入和 inbox 结构这两个核心接缝，却不改变模型可见历史。

**用携带编辑文本的替换用户消息，再以空的继续输入唤醒轮次。** 编辑文本会位于任何轮次之外，Chat 无法把它归入下一次交流，唤醒输入也需要自己的展示方式。

## 后果

- 被撤回轮次中工具调用改动过的文件不会恢复；编辑器在其操作旁说明这一点。
- 当事件不是开启其轮次的已发送用户消息（`NOT_A_USER_MESSAGE`）、消息已不再到达模型（例如压缩或更早的撤回之后，`NOT_ON_SURFACE`）或存在待处理的排队输入（`PENDING_INPUT`）时，编辑以 `session/edit-unavailable` 拒绝；运行中的 Session 返回 `session/agent-busy`，因此任何运行期间 Chat 都会禁用铅笔。
- surface 节点 0 处的系统提示词头部从不被遮蔽；编辑第一轮时从节点 1 开始撤回。
- 若撤回落在已加载窗口最早轮次之外，只有在该轮次的开始加载后才会隐藏其更早的事件；在此之前，窗口隐藏撤回之前它持有的全部内容。
- Liveshare 把 `session/editMessage` 归为仅所有者可用。
